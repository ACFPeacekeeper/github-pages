# docs/website/ — application notes

[Docusaurus](https://docusaurus.io/) (docs/guides site) + [TypeDoc](https://typedoc.org/) (API reference) + [Storybook](https://storybook.js.org/) (live component catalogue), wired into one deployable output.

For what the site contains and how to extend content, see [`README.md`](README.md). This file is about the app itself.

## How it works

- **Docs** (`/docs`): the classic preset's docs plugin points its `path` at this repo's [`../`](../) (i.e. `docs/`) — no copy step. `sidebars.ts` is explicit (not autogenerated).
- **Guides** (`/guides`): a second `@docusaurus/plugin-content-docs` instance (id `guides`) with `path` at the repo root and an `include` allow-list (`README.md`, `git/CONTRIBUTING.md`, `.agent/AGENTS.md`) — see `sidebarsGuides.ts`.
- **API Reference** (`/docs/website/api-docs`): `npm run gen:api` runs `typedoc` against [`../../lib/`](../../lib/), then `scripts/fix-api-links.mjs` rewrites internal cross-links into absolute site paths. Output is registered on the **default** docs instance (nested under `docs/website/api-docs/`).
- **Storybook** (`/storybook/index.html`): `.storybook/main.ts` configures `@storybook/react-vite` against the main site's real components at `src/frameworks/react/components/`. Next.js imports are aliased to `.storybook/shims/`.

  **Known limitation:** react-docgen-typescript skips files outside this package's tree, so every story ships hand-written `argTypes` instead of auto prop tables.

## Local dev

```bash
npm install
npm start          # Docusaurus: http://localhost:3000/github-pages/docs-site/
npm run storybook  # Storybook: http://localhost:6006
```

## Build

```bash
npm run build
```

Runs, in order: `gen:api` (TypeDoc), `build-storybook` (into `storybook-dist/`), `docusaurus build` (into `build/`), then `postbuild` copies `storybook-dist/` into `build/storybook/`.

```bash
npm run serve      # serve build/ locally
```

## Notable implementation gotchas

- **`lucide-react` here is pinned to `0.469.0`**, independent of the main site's pin, for React 19 peer compatibility with Docusaurus 3.10.
- **Vite is pinned to `^5`**, not the Storybook default — newer experimental Vite builds fail to parse some story JSX.
- **Tailwind/PostCSS are scoped to Storybook** via inline `viteFinal` config (and `.cjs` filenames) so Docusaurus Infima styling is not reset by Tailwind preflight.
