# docs/website/

A documentation dashboard for this repository, combining three tools rather than one custom app: [Docusaurus](https://docusaurus.io/) for the docs/guides site itself, [TypeDoc](https://typedoc.org/) for generated API reference, and [Storybook](https://storybook.js.org/) for a live, interactive catalogue of the site's React components.

The actual project lives in [`react/`](react/) — see [`react/README.md`](react/README.md) for local dev/build commands and implementation notes. This file covers what the *site* contains and how to extend it; `react/README.md` covers how the *app* is built.

## What's on the site

- **Home (`/`)** — a hero + four cards linking into the three sections below (Storybook is the fourth).
- **Docs (`/docs`)** — every file under this repository's [`docs/`](../) directory, read directly (no copy/sync step): architecture, dependencies, dev setup, testing, troubleshooting, the ADRs, and the roadmap/changelog/research under `docs/moon/`. Also hosts the generated API reference at `/docs/website/react/api-docs` (see below).
- **Guides (`/guides`)** — a small, hand-curated set of repo-wide guides that live *outside* `docs/`: the root [`README.md`](../../README.md), [`git/CONTRIBUTING.md`](../../git/CONTRIBUTING.md), and [`.agent/AGENTS.md`](../../.agent/AGENTS.md). Deliberately not a full repo crawl — see "Adding new information" below.
- **API Reference (`/docs/website/react/api-docs`)** — [TypeDoc](https://typedoc.org/) + [`typedoc-plugin-markdown`](https://typedoc-plugin-markdown.org/) output for [`lib/`](../../lib/)'s exported functions and types (currently `lib/markdown.ts`). Regenerated by `npm run gen:api`.
- **Storybook (`/storybook/index.html`)** — the site's UI/layout components, rendered live against their actual source (not a copy), with hand-written `argTypes` (control + description per prop) in each story's "Docs" tab — [react-docgen-typescript](https://github.com/styleguidist/react-docgen-typescript) is configured but doesn't currently attach prop info in this setup; see `react/README.md`'s "Known limitation" note.

## Running it locally

```bash
cd docs/website/react
npm install
npm start          # http://localhost:3000/github-pages/docs-site/
npm run storybook  # http://localhost:6006, separately
```

See [`react/README.md`](react/README.md) for the build/preview commands and how the three tools are wired together into one deployable output.

## Adding new information

**A new page under `docs/`**: just add the Markdown file under the right `docs/` subdirectory, then add it to [`react/sidebars.ts`](react/sidebars.ts)'s explicit `docsSidebar` array. It's explicit rather than autogenerated so ordering doesn't depend on adding Docusaurus-specific frontmatter to files that are also read plainly on GitHub and by other tooling — see that file's own comment.

**A new repo-wide guide that lives outside `docs/`**: add it to the `include` array of the `guides` plugin instance in [`react/docusaurus.config.ts`](react/docusaurus.config.ts), and to [`react/sidebarsGuides.ts`](react/sidebarsGuides.ts). Kept short and deliberate rather than a full repo walk, same reasoning as `EXTRA_SECTIONS` in comparable setups elsewhere: a file doesn't appear here just by existing.

**API reference changes**: edit [`lib/markdown.ts`](../../lib/markdown.ts) (or add a new file there) and run `npm run gen:api` — no manual doc editing, it's fully generated. New exported functions/types show up automatically; new *files* need an entry in `react/typedoc.json`'s `entryPoints` and `react/sidebars.ts`'s `apiSidebar`.

**A new component story**: add a `.stories.tsx` file under [`react/stories/`](react/stories/), importing the real component from `../site-src/components/...` (see `react/README.md`'s "Notable implementation gotchas" for why not a `@/...` alias here). No site config changes needed — Storybook discovers it automatically.

## Important things to know

- **Nothing here duplicates content.** Docs and guides are read directly from their real locations at build time (Docusaurus's `path`/`include` options); Storybook imports the real component sources via a symlink (`react/site-src`), not a copy. Edit the source, not the site.
- **Three separate build steps, one deployable output.** `npm run build` in `react/` runs TypeDoc, then Storybook's build, then Docusaurus's build, then copies the Storybook output into Docusaurus's `build/storybook/` — see `react/package.json`'s `pre`/`post` build hooks.
- **This site's own `docs/website/react/api-docs/` is itself inside the repo's `docs/` tree**, which is why it's registered on the *default* Docusaurus docs-plugin instance (not a separate one) — see the comment on that instance in `react/docusaurus.config.ts` for the Docusaurus quirk this works around.
- **`README.md` here vs. `react/README.md`**: this file is about the *site* (what's on it, how to use it, how to add content); `react/README.md` is about the *app* (how the three tools are wired, local dev, build mechanics). Update the one that actually changed.
