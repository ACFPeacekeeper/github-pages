# docs/website/

A documentation dashboard for this repository, combining three tools rather than one custom app: [Docusaurus](https://docusaurus.io/) for the docs/guides site itself, [TypeDoc](https://typedoc.org/) for generated API reference, and [Storybook](https://storybook.js.org/) for a live catalogue of the main site's React components.

The package lives directly in this directory (not a nested `react/` subfolder), matching the flattened layout used by org docs sites such as Project-Mobile-Fortress `docs/website/`. See [`APP.md`](APP.md) for how the three tools are wired; this file covers what the *site* contains and how to extend it.

## What's on the site

- **Home (`/`)** — a hero + four cards linking into the sections below (Storybook is the fourth).
- **Docs (`/docs`)** — every file under this repository's [`docs/`](../) directory, read directly (no copy/sync step): architecture, dependencies, dev setup, testing, troubleshooting, the ADRs, and the roadmap/changelog/research under `docs/moon/`. Also hosts the generated API reference at `/docs/website/api-docs` (see below).
- **Guides (`/guides`)** — a small, hand-curated set of repo-wide guides that live *outside* `docs/`: the root [`README.md`](../../README.md), [`git/CONTRIBUTING.md`](../../git/CONTRIBUTING.md), and [`.agent/AGENTS.md`](../../.agent/AGENTS.md). Deliberately not a full repo crawl — see "Adding new information" below.
- **API Reference (`/docs/website/api-docs`)** — [TypeDoc](https://typedoc.org/) + [`typedoc-plugin-markdown`](https://typedoc-plugin-markdown.org/) output for [`lib/`](../../lib/)'s exported functions and types (currently `lib/markdown.ts`). Regenerated by `npm run gen:api`.
- **Storybook (`/storybook/index.html`)** — the main site's UI/layout components under `src/frameworks/react/components/`, rendered live with hand-written `argTypes` (see `APP.md`'s "Known limitation" note).

## Running it locally

```bash
cd docs/website
npm install
npm start          # http://localhost:3000/github-pages/docs-site/
npm run storybook  # http://localhost:6006, separately
```

See [`APP.md`](APP.md) for build/preview commands and how the three tools are wired into one deployable output.

## Adding new information

**A new page under `docs/`**: add the Markdown file under the right `docs/` subdirectory, then add it to [`sidebars.ts`](sidebars.ts)'s explicit `docsSidebar` array. Explicit rather than autogenerated so ordering doesn't depend on Docusaurus-specific frontmatter on shared files.

**A new repo-wide guide outside `docs/`**: add it to the `include` array of the `guides` plugin instance in [`docusaurus.config.ts`](docusaurus.config.ts), and to [`sidebarsGuides.ts`](sidebarsGuides.ts).

**API reference changes**: edit [`lib/markdown.ts`](../../lib/markdown.ts) (or add a new file there) and run `npm run gen:api`. New *files* need an entry in `typedoc.json`'s `entryPoints` and `sidebars.ts`'s `apiSidebar`.

**A new component story**: add a `.stories.tsx` file under [`stories/`](stories/), importing the real component from `../../../src/frameworks/react/components/...`. Storybook discovers it automatically.

## Important things to know

- **Nothing here duplicates content.** Docs and guides are read from their real locations at build time; Storybook stories import the main site's component sources directly.
- **Three separate build steps, one deployable output.** `npm run build` runs TypeDoc, then Storybook, then Docusaurus, then copies Storybook into `build/storybook/`.
- **Generated API docs live at `docs/website/api-docs/`** (under the default docs-plugin path), registered on the default Docusaurus docs instance — see comments in `docusaurus.config.ts`.
- **`README.md` vs `APP.md`**: this file is about the *site*; `APP.md` is about the *app* (tooling, layout, build mechanics).
