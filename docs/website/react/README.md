# docs/website/react/

[Docusaurus](https://docusaurus.io/) (docs/guides site) + [TypeDoc](https://typedoc.org/) (API reference) + [Storybook](https://storybook.js.org/) (live component catalogue), wired into one deployable output.

For what the site actually contains and how to navigate/extend it, see [`../README.md`](../README.md). This file is about the app itself.

## How it works

- **Docs** (`/docs`): the classic preset's docs plugin points its `path` straight at this repo's [`../../`](../../) (i.e. `docs/`) — no copy step, no sync script. `sidebars.ts` is explicit (not autogenerated) so ordering doesn't depend on adding Docusaurus-specific frontmatter to files that are also read plainly elsewhere.
- **Guides** (`/guides`): a second `@docusaurus/plugin-content-docs` instance (id `guides`) with `path` at the repo root and an `include` allow-list of three specific files (`README.md`, `git/CONTRIBUTING.md`, `.agent/AGENTS.md`) — deliberately curated, see `sidebarsGuides.ts`.
- **API Reference** (`/docs/website/react/api-docs`): `npm run gen:api` runs `typedoc` (with `typedoc-plugin-markdown`) against [`../../../lib/`](../../../lib/), then `scripts/fix-api-links.mjs` rewrites the generated pages' internal cross-links (TypeDoc emits relative, `.md`-suffixed links between them) into absolute site paths — a Docusaurus link-resolution bug mis-threads the webpack import for a relative link's target through the wrong docs-plugin instance's generated-content folder otherwise. The output is registered on the **default** docs instance, not its own — see the comment on that instance in `docusaurus.config.ts` for why (it's physically nested under `docs/`, and Docusaurus resolves plugin ownership by path prefix for this particular mechanism regardless of which instance's `include` lists a file).
- **Storybook** (`/storybook/index.html`): `.storybook/main.ts` configures `@storybook/react-vite` (with `typescript.reactDocgen: 'react-docgen-typescript'`) against the real component sources — stories import directly from `../../../../src/components/...`, no copy or symlink involved. Next.js-specific imports (`next/image`, `next/link`, `next/navigation`) are aliased to small stand-ins under `.storybook/shims/`, since Storybook here runs on plain Vite, not Next.

  **Known limitation:** the docgen plugin logs "Skipping docgen ... because it is not included in the active TypeScript project" for every real component and never attaches prop-table data, because those files live outside this package's own directory tree — `vite-plugin-react-docgen-typescript` scopes its analysis to files under the Storybook project root, full stop (a symlink into that root was tried and made no difference; docgen checks the file's real, resolved path, not the specifier it was imported through). Every story ships explicit `argTypes` (control + description per prop) as the practical substitute — hand-written rather than introspected. Revisit only if a future Storybook/plugin version supports analyzing files outside the project root.

## Local dev

```bash
npm install
npm start          # Docusaurus dev server: http://localhost:3000/github-pages/docs-site/
npm run storybook  # Storybook dev server: http://localhost:6006
```

## Build

```bash
npm run build
```

Runs, in order: `gen:api` (TypeDoc), `build-storybook` (into `storybook-dist/`), `docusaurus build` (into `build/`), then a `postbuild` step that copies `storybook-dist/` into `build/storybook/` so the whole dashboard ships as one static output.

```bash
npm run serve      # serve build/ locally
```

## Project layout

```

├── docusaurus.config.ts     # site config: 2 docs-plugin instances (default, guides), navbar/footer
├── sidebars.ts              # explicit sidebar for the "default" instance (docs/ + generated API reference)
├── sidebarsGuides.ts        # explicit sidebar for the "guides" instance
├── typedoc.json             # entry points: ../../../lib/*.ts -> api-docs/ (generated, gitignored)
├── typedoc.tsconfig.json    # standalone tsconfig for TypeDoc (the main repo's own tsconfig

├── tailwind.config.cjs      # Storybook-only Tailwind config (deliberately not postcss.config.js
│                             # at the project root — see its own comment for why)
├── scripts/
│   └── fix-api-links.mjs    # post-processes TypeDoc's markdown output, see "How it works" above
├── .storybook/
│   ├── main.ts               # framework config, Next.js shims, Tailwind wiring
│   ├── preview.tsx           # global decorators (dark/light theme toggle), Tailwind entry CSS
│   └── shims/                # next/image, next/link, next/navigation, and the profile-pic asset
├── stories/                  # *.stories.tsx, one per showcased component
└── src/
    ├── css/custom.css        # Infima theme variables, matching the main site's Tailwind palette
    └── pages/index.tsx       # the hero + cards homepage
```

## Notable implementation gotchas

- **`lucide-react` here is pinned to `0.469.0`, independent of the main site's `^0.383.0`.** This project's `react`/`react-dom` are v19 (Docusaurus 3.10's own requirement), and `lucide-react@0.383.0`'s peer range tops out at React 18; `0.469.0` is the oldest version with the same icon export names that also supports React 19.
- **Vite is pinned to `^5`, not the `@storybook/react-vite` default.** The version that gets installed otherwise (Vite 8, rolldown-powered) fails to parse JSX inside plain object literals in a few of the story files — a bug in that still-experimental build, not in this project's code.
- **The generated API reference lives on the `default` docs-plugin instance, physically inside `docs/`, even though it's *this* project's output.** See the comment on that instance in `docusaurus.config.ts`.
